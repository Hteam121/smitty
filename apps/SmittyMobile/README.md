# Smitty for iPhone and Apple Watch

A thin front door to Smitty while you are away from the Mac: **Chat**, **Inbox** (approvals,
questions, screenshot reviews) and **Sessions** (what each agent is doing, step by step).
The apps only talk to the Supabase hub (`supabase/migrations/0001_hub.sql`); the Mac mirrors
its activity up and drains the `commands` queue. When the Mac is offline the app shows the last
known state and anything you send waits as "queued".

No third-party packages: plain `URLSession` against PostgREST / GoTrue / Storage.

## Layout

```
project.yml            xcodegen spec: targets Smitty (iOS 17+) and SmittyWatch (watchOS 10+)
Shared/                compiled into both apps
  Theme.swift          the dashboard palette (navy / cream / coral) and glass cards
  Models.swift         rows and the hub_state snapshot (sessions, approvals, mac online/offline)
  HubConfig.swift      hub URL + publishable key + tokens, kept in the Keychain
  HubClient.swift      auth (email + password), reads, command inserts, artifact download
  HubStore.swift       the observable store the screens read; polls every 3 s in the foreground
Smitty/                iPhone app: RootView (tabs + state pill), Chat (typed or dictated), Inbox, Sessions, Steps, Settings
  Dictation.swift      mic → live transcript in the chat field (Speech framework; Smitty only ever gets text)
SmittyWatch/           Watch app: "Tell Smitty" on top (one tap = dictation), approvals, unread inbox + Mark all read
```

## App icon

Both icons are the dashboard's particle cloud frozen mid-swirl (navy, cream dust, one coral
spark), generated by `design/icon.html`. To regenerate after a tweak, render it 1024×1024 with
`uv run smitty shot file://$PWD/design/icon.html --width 1024 --height 1024 --out /tmp/icon`
(from this folder; `shot` needs a URL, a bare path is taken for an image file) and copy the PNG
over `Smitty/Assets.xcassets/AppIcon.appiconset/AppIcon.png` and the watch one.

## Build

```bash
brew install xcodegen
cd apps/SmittyMobile
cp Local.xcconfig.example Local.xcconfig   # your bundle id prefix + Apple team id (git-ignored)
xcodegen generate            # writes Smitty.xcodeproj (git-ignored; never edit it by hand, edit project.yml)
open Smitty.xcodeproj
```

`Local.xcconfig` is where your own identity goes, so it never ends up in a commit:
`SMITTY_BUNDLE_PREFIX` (the apps become `<prefix>.smitty` and `<prefix>.smitty.watchkitapp`) and
`DEVELOPMENT_TEAM`. For the simulator you can skip the file: the defaults in `Config.xcconfig`
(`com.example`, no team) build fine unsigned. For a real iPhone both must be set; a free personal
Apple team is enough for your own devices (the app then needs re-installing every 7 days), a paid
developer account removes that limit. Then run the Smitty scheme on your iPhone; the watch app is
embedded and installs with it (or from the iPhone's Watch app if it does not appear by itself).

The **Smitty** scheme embeds the watch app, so Xcode needs the watchOS platform installed
(Xcode → Settings → Components → watchOS simulator, a few GB).

### Simulator: phone + watch

In Xcode, pick the run destination **iPhone 17 Pro** (the paired one, listed as
"iPhone 17 Pro + Apple Watch Series 11 (46mm)" under *iOS Simulators*) and press Run. The phone
app launches; the watch app is installed on the paired watch simulator with it — open the
watch simulator window (Simulator → Window, or File → Open Simulator) and tap Smitty there.
Sign in on the phone; the watch picks the session up over WatchConnectivity (tap *Share sign-in
with Watch again* in the phone's Settings if it doesn't).

Without Xcode, from this folder:

```bash
xcodebuild -project Smitty.xcodeproj -scheme Smitty -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO build
```

then install the built `Smitty.app` on the phone with `xcrun simctl install <phone udid> …/Smitty.app`
and its `Watch/SmittyWatch.app` on the paired watch (`xcrun simctl list pairs` shows both udids),
and `xcrun simctl launch` each bundle id (`<prefix>.smitty`, `<prefix>.smitty.watchkitapp`).

Your Simulator app remembers each simulator's installed apps and sign-in; to start clean,
`xcrun simctl uninstall <udid> <prefix>.smitty`.

## Connect it

1. Create the Supabase project and run `supabase/migrations/0001_hub.sql` in the SQL editor.
2. Authentication → Providers: enable **Email**. (No Sign in with Apple: it needs the paid
   account's entitlement + provider setup for no gain on a single-user hub.)
3. Authentication → Users: add yourself with an email + password. Then turn **off**
   "Allow new users to sign up" — this hub is single-user and row-level security grants every
   signed-in user full access.
4. In the app's Settings (gear, or the first screen): paste the project URL
   (`https://xxxx.supabase.co`) and the **publishable** (legacy: anon) key from Project
   Settings → API Keys, then sign in with that email + password. The phone hands the sign-in to
   the watch over WatchConnectivity; nothing to type there.
5. On the Mac, give Smitty the same URL and the **secret** (legacy: service role) key
   (`~/.smitty/hub.json`, see `docs/hub-setup.md`) so it starts mirroring and draining commands.

The publishable key is public by design; the secret key must stay on the Mac.

## What each screen sends

| Action | `commands` row |
| --- | --- |
| Chat composer / Watch "Tell Smitty" | `chat {text}` |
| Allow / Deny / Allow all on an approval | `approval {id, answer}` |
| Reply on an inbox card, Approve / Request changes on a screenshot | `notice_reply {id, text}` |
| Stop / Close / Send on a session | `session {key, action, text?}` |
| Viewing unread inbox cards / Mark all read | one `mark_read {ids}` per burst (coalesced ~0.7 s) |

Chat voice: the mic button (shown while the field is empty) starts live dictation; the words land
in the field as you speak, tapping the field switches back to typing, the arrow sends either way.
The first use asks for Microphone and Speech Recognition permission (strings in `project.yml`).

Approvals are always one explicit tap per answer (no swipe-to-approve), on the phone and on the
watch, and the whole question and command are shown before the buttons.

## Later phases (need the paid developer account and are not in this build)

- **APNs push** for approvals and finished sessions (database webhook → Edge Function → APNs),
  with Allow / Deny as notification actions on the watch.
- **TestFlight** distribution.
- **Live Activity** on the Lock Screen / Dynamic Island for the running session.
- **Realtime** subscriptions instead of 3-second polling (the migration already adds the tables
  to the `supabase_realtime` publication).
- Screenshots in the inbox depend on the Mac side writing `notices.image` and uploading to the
  `artifacts` bucket; the viewer, Approve and Request changes are already in the app.
